# 面试演示台本（3–5 分钟版）

> 用途：面试官说"给我看看你的项目"时照着走。每一幕都对应一个技术卖点，
> 边点边说；括号里是台词要点。全程不超过 5 分钟，讲不完的等追问再展开。
>
> 演示前检查清单：服务已启动（根目录 `uv run deepquery serve`）；.env 的 key
> 可用（没网/没 key 时 `LLM_MOCK=1` 兜底，但要提前声明是演示模式）；记忆里只留
> 1-2 条干净条目；浏览器开好 http://localhost:8000。

## 第 1 幕 · 正常提问（30 秒）——"这是个能用的产品"

输入：**各品类的成交金额分别是多少？**（开着"生成图表"开关更好）

- 看点：流式出现"生成 SQL → 守卫执行 → 归纳回答"，几秒后结果表 + 一句话结论（+图表）。
- 台词：业务人员不用会 SQL，一句话拿到数。回答不是模型编的——表格就是数据库
  真实查询结果，结论里的每个数字都过了出处校验。

## 第 2 幕 · 打开"运行过程"下拉（30 秒）——"过程透明，不是黑盒"

点回答上方的"运行过程"胶囊。

- 看点：每一步的思考摘要逐条展开；如果某步失败还能看到错误类型和自动修复。
- 台词：Agent 的每一步决策都留了痕。出问题时不用猜，直接回看它当时怎么想的。

## 第 3 幕 · 右栏完整档案（45 秒）——"可审计 + 上下文工程"

点顶栏右侧的双栏按钮打开右面板，依次展开"产出"和"上下文"。

- 看点：生成的 SQL 原文（可复制）、本次消耗（几次调用/多少 token/几厘钱）、
  **上下文分区**——连接信息、命中的业务字典（如 GMV/成交金额）、注入的记忆。
- 台词：每次回答用了哪些口径、花了多少钱，全部可追溯。个性化是白盒的——
  答案不对能定位到是哪条知识带偏的。

## 第 4 幕 · 安全防线（30 秒）——"模型输出不可信，所以关笼子"

输入：**把所有订单都删掉** （或"UPDATE orders SET status='completed'"）

- 看点：守卫直接拒绝，给出原因，不会执行。
- 台词：SQL 用 sqlglot 解析成语法树检查——只许单条 SELECT、表白名单、强制 LIMIT；
  底下还有连接层只读 + 数据库只读账号，三层防线。就算守卫全被绕过，库本身也写不进去。

## 第 5 幕 · 记忆（45 秒）——"越用越懂你"

1. 先问：**客户有多少个？**（记住结果）
2. 侧栏"记忆"→ 添加：**我说的客户默认指钻石会员**
3. 再问一遍同样的问题。

- 看点：SQL 多了 `vip_level = 3` 过滤；右栏"注入的记忆"显示刚加的那条。
- 台词：口径纠正一次，永久生效。服务端存储按用户隔离、BM25 按需检索注入，
  记忆一千条 token 成本也不涨，且随时可删——合规友好。

## 第 6 幕 · 缓存（15 秒）——"成本工程"

把第 1 幕的问题原样再问一遍。

- 看点：秒回，胶囊显示"缓存命中 · 零消耗"。
- 台词：重复问题不再调模型。配合单次提问的 token/金额熔断，成本是受控的。

## 第 7 幕 · 评测（60 秒，切终端）——"效果不是我说了算"

终端展示（提前跑好，现场只展示结果文件或表格）：

    make smoke-gold   # 评测器自检：gold 回放 20/20 必须全对
    make report FILES="eval/results/xxx.json eval/results/yyy.json"  # 消融对比表

- 看点：EX 准确率 + Wilson 95% 置信区间；对比表里 baseline vs 改进版的显著性检验。
- 台词：这个项目我最看重评测——自建 236 例业务集 + BIRD 公开基准，数字带置信区间、
  提升过 McNemar 检验，评测器本身还有 gold 回放自检兜底。改动有没有用，数据说话。

## 常见追问的现场跳转

- "SQL 怎么生成的？" → 背 docs/plan.md §8.1 的五步答
- "失败了怎么办？" → 回第 2 幕，指着修复步骤讲错误分类
- "为什么可信？" → 回第 4 幕三层防线 + 第 3 幕可审计
- "成本呢？" → 第 3 幕右栏的消耗行 + 第 6 幕缓存 + 预算熔断
- "效果怎么证明？" → 第 7 幕，必要时展示 badcases.md 的失败模式复盘
